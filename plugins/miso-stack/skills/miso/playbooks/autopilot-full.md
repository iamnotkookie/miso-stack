# Process an independent work queue

Use for: Build and verify independent changes with explicit publication gates.

## Procedure

1. Read the queue and define completion for each item. Identify which external actions are actually authorized.
2. Assign one owner per change and separate outputs. Avoid parallel edits to shared files.
3. Build, verify, and review each result against its own acceptance criteria.
4. Check for interactions between completed changes before integration.
5. Publish or merge only when the user and project policy authorize it. Deployments, data deletion, force-pushes, and messages keep their gates.
6. Report each item as complete, ready for approval, failed, or blocked with evidence.
