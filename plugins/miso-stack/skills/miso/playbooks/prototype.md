# Compare prototypes

Use for: Resolve a design or behavioral uncertainty with executable alternatives.

You own the decision. A prototype exists to settle a question cheaply, and then it goes away.

## Procedure

1. State the decision, the constraints, and the observable comparison criteria. If a run can settle the question, do not ask the user.
2. Create two or three small alternatives in separate scratch locations. Preserve existing user work.
3. Run the same interaction or workload against each candidate. Capture evidence and environmental conditions.
4. Compare measured results and implementation tradeoffs. Separate taste from measured behavior.
5. Select a candidate or report that the experiment did not settle the question. Do not promote a throwaway sketch as production-ready.
6. Keep the useful evidence and name any discarded design. Ask for the required approval before you delete scratch data.

## Completion evidence

Comparable observations support the chosen design or explicitly show an unresolved result.

## Reply

State the decision, the winner or the lack of one, and the evidence. Use a table for the candidates.
