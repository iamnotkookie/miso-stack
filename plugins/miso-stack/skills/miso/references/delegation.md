# Delegation contract

Read the current harness map before spawning. Session and project restrictions take precedence. Use only callable tools and accepted parameters. Do not infer that an installed plugin grants a cloud computer or permission to transmit data.

Each worker receives the task, permitted files, baseline revision or file hashes, relevant skill paths, output location, proof criteria, and stop condition. A child must read `miso` and its host map rather than depend on inherited context. Keep credentials and unrelated history out of worker prompts.

Use the harness default model unless project configuration names a supported override. The same model can perform independent attempts; label them as such. If a tool rejects a configured model, report the mismatch and use the default only when project instructions permit fallback.

Separate mutable outputs. Share a read-only source tree where safe. A worktree needs an existing repository and cannot justify initializing Git. One process owns a live app verification session. Other workers can inspect source or use separate instances.

The lead verifies returned files and important commands, combines changes, and reruns integration checks. Record failed and cancelled work. Wait for or stop owned workers before completion. If no worker facility exists, perform the steps serially and report the limitation.
